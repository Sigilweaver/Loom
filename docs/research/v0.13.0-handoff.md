# v0.13.0 handoff notes

Work was split across parallel agents and stopped early to save budget.
This file records what each area finished, what it found but did not
fix, and the manual steps needed to ship. Delete it once v0.13.0 is out
and the open items are filed as issues.

## Release steps (manual)

1. Confirm repo secrets exist: `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`,
   `R2_BUCKET_NAME`, `R2_ENDPOINT_URL` (optional `R2_CDN_URL`). They are now
   used by `mirror-release.yml`, which runs when a release is published.
2. Merge this branch to `main`. Make sure `ci.yml` has a passing run on the
   exact commit you will tag (docs-only commits skip CI; dispatch it by hand
   if needed). `release.yml` refuses to build without one.
3. Write the `CHANGELOG.md` entry for v0.13.0, then tag `v0.13.0` on `main`.
4. `release.yml` creates a DRAFT release. Review the assets, then click
   Publish. Publishing triggers the R2 mirror and the Docker image build.
   Tags containing `-` (e.g. `v1.0.0-rc.1`) become pre-releases and never
   update the stable download index or the `latest` Docker tag.
5. Watch the first `docker-build-check` CI job and the Docker build: the hub
   Dockerfile fix (Bun instead of `npm ci`) could not be tested with a real
   Docker daemon here.

## Hub backend

Done: #142 (ruff/mypy enforced), #81 (no shared-secret fallback), #71
(least-loaded server selection). Hub-triggered runs now execute as the
triggering user / schedule creator (fixes a 500 from `/internal/authorize`).

Found, not fixed:
- **Audit chain verify is broken (bug).** `_compute_hash` runs before
  `event.id` and `event.timestamp` are set, so `/api/v1/audit/verify`
  reports every event as a mismatch. Fix: assign id/timestamp before
  hashing, take an advisory lock around the previous-hash read (concurrent
  writers fork the chain today), add a `hash_version` column so legacy rows
  are skipped, and include `auth_method`, `client_ip`, `user_agent`,
  `server_id` in the hash. The `AuditEvent` docstring claims a DB trigger
  enforces append-only; none exists. (#110)
- **Server registration bug.** `POST /servers` with a null `auth_token`
  matches any other server whose token is null and overwrites it.
- #69 duplicate scheduled runs: every replica runs its own APScheduler.
  Plan: `schedule_fires` table, unique `(schedule_id, fire_time)` with
  fire_time floored to the minute, claim by INSERT and catch IntegrityError.
  Schedule create/update/delete also only registers on the replica that
  handled the request.
- #68 durable executions: add `executions.heartbeat_at` refreshed every
  ~15s; a startup + periodic sweep marks stale queued/running runs as
  failed ("interrupted"). Keep references to `asyncio.create_task` runners,
  cancel on shutdown, and do not let a finished result overwrite
  `cancelled`.
- Cruft candidates (unverified): unused config fields `secret_key`,
  `algorithm`, `access_token_expire_minutes`, `jwt_private_key`,
  `jwt_issuer` (and `_INSECURE_DEFAULT` in `main.py`; `SECRET_KEY` is still
  required at boot for no reason; set `extra="ignore"` before removing so
  old `.env` files still load); legacy `TokenTracker` aliases,
  `RequireOwner`, `extract_hub_connections`, `pause_schedule` /
  `resume_schedule` / `reset_scheduler`, `poll_single_server`,
  `ExecutionResult`, `ExecutionReportSchema`,
  `ExecutionRecordListResponse`.
- Larger: executions, schedules and permission changes are not audited;
  `Server.auth_token` stored in plaintext (encrypt with the Fernet key);
  migration entrypoint has no lock for concurrent replicas; health poller
  never prunes failure maps for deleted servers; no migration tests; some
  tests spawn background tasks against the non-test database.
- #118 cookie sessions, backend side: set an httpOnly, Secure, SameSite
  cookie at login, clear at logout, accept cookie or Bearer in the auth
  dependency, add CSRF protection (double-submit or Origin check) for
  state-changing routes.
